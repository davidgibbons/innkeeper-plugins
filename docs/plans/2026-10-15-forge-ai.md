# forge-ai Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go plugin, `forge-ai`, that offers the `action` capability: it
writes, revises, tightens, and evaluates character cards with an LLM.

**Architecture:** One `main` package in `forge-ai/`, like the other plugins.
Instance settings pick an any-llm-go provider. Each action renders an
embedded `text/template` system and user prompt, streams the model's JSON,
reports progress per field, and maps the result to a proposal or a report.
Library tools go to the core as `library.call` through any-llm-go tool
calling.

**Tech Stack:** Go 1.27, `github.com/davidgibbons/innkeeper/protocol`,
`github.com/mozilla-ai/any-llm-go` v0.9.0, `text/template` and `embed`.

**Source design:** core repo, `docs/superpowers/specs/2026-10-14-forge-design.md`,
sections "The AI plugin" and "Tests". Protocol: core `docs/protocol.md`,
section `action`.

## Decisions

| Topic | Decision |
|---|---|
| Core version | The `action` protocol is in core `e42616c`; `go.mod` pins it. |
| Prompt syntax | Templates use `[[` and `]]` delimiters, so the roleplay macros `{{char}}` and `{{user}}` pass through untouched. |
| Output format | Every prompt asks for one JSON object keyed by CCv3 data keys (`first_mes`, not `firstMessage`). The generator's `##` section format becomes JSON. |
| Editable keys | Whole-card actions send and take back only the prose keys: `name`, `description`, `personality`, `scenario`, `first_mes`, `mes_example`, `system_prompt`, `post_history_instructions`, `creator_notes`, `tags`. The proposal is the draft with those keys replaced, so `extensions` and the rest survive. |
| Progress | When a key the action writes starts in the streamed object, send "Writing {Label} ({n} of {total})" with `done = n-1`. Each request counts from 1 again. |
| JSON start | The object is read from the first `{` that parses, since prose before it may hold `{{char}}`. |
| `<think>` | Complete `<think>…</think>` blocks are removed, and an unclosed one at the end is ignored until it closes. A `</think>` with no opening tag, as Qwen3 and R1 templates produce, drops everything before it. |
| Model values | `null` means unchanged. Tags written as comma-separated text are split. |
| No tool support | All providers report `CompletionTools`. If the first request, with tools, fails with `ErrInvalidRequest`, it is retried once without them, and the run continues with only the explicit context. Later rounds aren't retried. |
| Tool rounds | At most 8 requests; the last offers no tools, so the model must answer. The loop checks the context before each round and after each tool call, and a `-32602` from `library.call` (the run has ended) fails the run. |
| Streamed tool calls | any-llm-go passes each provider's streaming shape through with no index. The plugin merges per provider: Anthropic resends the whole call under its ID, so a known ID replaces it; Ollama's IDs are numbered within each chunk, so every call is new; the rest append fragments with an empty or known ID to their call. An upstream fix, an `Index` on `ToolCall` or unique Ollama IDs, would remove this. |
| Evaluate dimensions | The generator's evaluate prompt has six dimensions plus an overall score, not seven. Keep its six. Add a `summary` key, which a report requires. |
| Field-action presets | "Character Architect's presets" aren't in `~/git`. Write concise presets for tighten, expand, to-prose, and rewrite. |
| Additions | `additions` is an object with one string property per action ID in `plugin.toml`. A test keeps those properties and the action list equal. |

### Task 2: Streamed output (`stream.go`)

Tests first, in `stream_test.go`:

- `TestVisibleDropsThinkBlocks`: `<think>a</think>{"x":1}` gives `{"x":1}`;
  an unclosed `<think>…` hides everything after it.
- `TestStartedKeysOnPartialOutput`: for ```` ```json\n{"name":"Bo","description":"A ```` the
  started keys are `name, description`.
- `TestParseObjectAfterThinkAndFence`: a fenced object after a think block
  parses; prose with no object is an error that quotes the start of the output.

Implementation:

```go
func visible(s string) string            // strip think blocks
func startedKeys(s string) []string      // top-level keys begun so far
func parseObject(s string) (map[string]json.RawMessage, error)
```

`startedKeys` runs a `json.Decoder` from the first `{` and stops at the
first incomplete token.

### Task 3: Prompts (`prompts.go`, `prompts/`)

Tests first, in `prompts_test.go`:

- `TestEveryActionRenders`: each action renders a non-empty system and user
  prompt for a sample card, keeps `{{char}}` and `{{user}}`, and names every
  key it expects back.
- `TestHouseStyleAndAdditionInSystemPrompt`: house style goes in every
  action's system prompt; an addition goes only in its own action's.
- `TestContextInUserPrompt`: an attached card's name and data appear.
- `TestAdditionsMatchActions`: `plugin.toml`'s `additions` properties are the
  action IDs.

Templates: `generate`, `revise`, `evaluate`, `tighten-card`, `change-pov`,
`examples`, `field` (shared user prompt) plus one system prompt per field
preset, and a shared `context` block. Ported from
`character-card-generator` commit `0b2f57e`.

### Task 4: Actions (`actions.go`)

Tests first, in `actions_test.go`:

- `TestActionsValidate`: every declaration passes `protocol.Action.Validate`.
- `TestFieldActionProposalChangesOnlyItsField`.
- `TestWholeCardProposalKeepsOtherKeys`: `extensions` survives revise.
- `TestEvaluateReport`: model JSON maps to a report with score, six
  dimensions, findings (contradictions high, misplaced content medium with a
  move), and suggestions; `Report.Validate` passes.
- `TestChangePOVNeedsPointOfView`: empty inputs are `-32602`.

### Task 5: Settings and providers (`settings.go`)

Tests first, in `settings_test.go`:

- `TestOpenAIRequiresKey`, `TestLocalProvidersNeedNoKey` (openai-compatible,
  ollama, llamacpp, llamafile), `TestUnknownProvider`, `TestModelRequired`.

Provider map: `openai-compatible` is `openai.NewCompatible` with
`RequireAPIKey: false`; the rest call their package's `New` with
`WithAPIKey` and `WithBaseURL` when set.

### Task 6: Chat loop and the run (`chat.go`, `main.go`)

Tests first, in `run_test.go`, with an `httptest` server speaking
OpenAI-compatible SSE and a fake host: two `protocol.Conn`s over pipes.

- `TestRunStreamsProgressPerField`: a generate run sends "Writing Name (1 of
  9)" onward and replies with the proposal and `raw`.
- `TestLibraryToolCallAnsweredByHost`: the model calls `get_card`; the host
  gets `library.call` with the run token; the second request carries the tool
  result; the run finishes.
- `TestNoToolsWithoutLibrary`: a field action sends no `tools`.
- `TestRetriesWithoutToolsWhenRejected`: a 400 to the request with tools is
  followed by one without, and the run succeeds.
- `TestRunWithoutModelFails`: no settings gives an error, not `-32601`.
